lynx Changelog

DNS-over-HTTPS proxy

v0.6.1

2026-07-05

  • Fix: Error rate inflated >100% in GUI — queries_ was only incremented on successful DoH queries (in recordLatency()), but errors_ grew independently from backpressure rejections. Denominator now includes every admitted DNS query via recordDnsQuery() at receive time.
  • Fix: Duplicate watchdog processes racing on proxy file — ensure_watchdog() switched from pgrep -f to PID file (/tmp/lynx-watchdog.pid) with kill -0 check. Prevents stale or duplicate watchdogs from writing conflicting proxy state.

v0.6.0

2026-07-05

  • Feature: Turbo threader — aggressive thread pool scaling when pending queue exceeds 50 (+8 threads/cycle, up to 48). Capped decay prevents prolonged PID suppression after load drops. (AutoTuner)
  • Feature: Backpressure in thread pool — tryEnqueue() rejects tasks when queue ≥ 2000. Rejected queries return SERVFAIL to client instead of silently dropping. (ThreadPool)
  • Fix: ThreadPool::resize() uses liveCount_ instead of workers_.size() — after shrink, workers_.size() never decreased, so resize() refused to spawn new threads, permanently understaffing the pool. (dns_server.cpp:59)
  • Fix: workerLoop() double-decrement of liveCount_ — maybeShrink() already decrements via CAS; the unconditional fetch_sub(1) at loop exit caused each shrink to remove 2 workers instead of 1. (dns_server.cpp:109)
  • Fix: async_send_to buffer use-after-free in onUdpReceive rejection path — wire was a local vector destroyed before the async operation completed. Captured via shared_ptr.
  • Fix: Uncaught exception from DnsMessage::parse() in onUdpReceive rejection path — wrapped in try-catch.
  • Performance: ThreadPool::MAX_WORKERS 32 → 64; AutoTuner::MAX_THREADS 16 → 48. Enables scaling to higher concurrency under load.
  • Performance: Restart window reduced from 2s to 0.5s in lynx-loop.sh — minimizes DNS downtime on crash.

v0.5.0

2026-07-04

  • Performance: Pre-built HTTP header prefix per connection — eliminates ostringstream allocation per DNS query (Connection::buildHeaderPrefix()).
  • Performance: In-place HTTP response parsing with string_view — zero-copy header/body extraction in both exchange() and healthCheck().
  • Performance: Reconnect thread-per-failure → single reconnect worker thread with work queue — prevents thread storms under network flips (ConnectionController).
  • Performance: Reconnect uses stream pointer instead of stale vector index — eliminates race on reconnections after vector modification.
  • Performance: Reconnect releases mutex during blocking TCP/SSL handshake — prevents all maintenance threads from blocking during slow reconnects.
  • Performance: Sharded rate limiter (16 FNV-1a buckets) — reduces mutex contention under high QPS (DnsServer).
  • Performance: CacheEntry duplicate question field removed — saves memory per cache entry (CachingResolver).
  • Performance: _mm_pause() in turboLookup/turboInsert spinloops — reduces power/contention on contended atomics.
  • Performance: refreshEntry uses std::move(reply) instead of reply->copy() — avoids full DNS message copy during refresh.
  • Performance: thread_local query counter replaces static std::atomic<int> — avoids atomic contention per query.
  • Performance: LatencyRing marked alignas(64) — prevents false sharing between threads (PerfMonitor).
  • Performance: nameToWire() avoids string copy for trailing dot; wireToName() reserves 64 bytes.
  • Performance: makeHealthQuery() returns static const buffer — avoids per-call allocation.
  • Fix: raceUpstreams() captures wire by value instead of by reference — prevents use-after-free when async tasks outlive the caller.
  • Fix: Missing memcpy in exchange() and healthCheck() response reassembly — body data was silently discarded (bug introduced during string_view refactor).
  • Fix: Reconnect loop in run() still used stale reconnectAsync(idx) — now pushes ReconnectWork to queue.
  • Fix: Reconnect queue LIFO (pop_back) → FIFO (pop_front) — ensures oldest failure reconnects first.
  • Fix: snprintf return value unclamped in Content-Length formatting — potential string_view over-read.
  • Fix: maintain() modifies pool.connections without growMutex — data race with concurrent getNextConnection().
  • Fix: Socket closed before connected flag cleared in probeAllIdle() and run() — race window allowed writes to closed sockets.
  • Fix: getNextConnection() reads pool.connections without lock — UB when vector resizes concurrently.
  • Fix: connCtrl_.manage() called even on connection failure — zombie entries registered in ConnectionController.
  • Fix: reload() modifies proxy config without synchronization — data race with concurrent query threads.
  • Fix: Socket not re-opened after proxy failure in openFunc() — direct fallback path used a closed socket.
  • Fix: Socket open() failure not propagated in openFunc() — code continued to connect() on closed socket.
  • Fix: Aggregate init order-dependent on struct layout in manage() — replaced with explicit member initialization.
  • Refactor: Reconnect worker loop extracted into ConnectionController::reconnectLoop() member function.
  • Architecture: Architecture diagram replaced with lynxdohdnsmap.png visual in README.

v0.4.0

2026-07-03

  • Feature: Hardcoded IP fallback for DoH upstream resolution (http_resolver.cpp) — lynx works on any network regardless of /etc/resolv.conf. Built-in IP table for dns.google, cloudflare-dns.com, dns.quad9.net.
  • Feature: start.sh unified launcher — {start|stop|restart|status|logs} manages the full lynx stack.
  • Feature: lynx-watchdog.sh — auto-detects WORK/HOME network every 10s by probing proxy TCP connect. Updates ~/.lynx-proxy and ~/.proxy-env, sends SIGHUP to lynx on switch.
  • Feature: lynx-loop.sh — persistent supervisor that restarts lynx on crash and ensures watchdog stays alive.
  • Feature: Dashboard SSE endpoint (/api/stream) — real-time JSON push every 1s with latency, cache, connection, and auto-tuner stats.
  • Feature: Modern web dashboard UI (www/) with uPlot charts, matrix rain background, and real-time stat cards.
  • Fix: heap-use-after-free in CachingResolver::refreshEntry() — refresh thread no longer iterates the cache map across unlock boundaries. Keys are collected while holding the lock, then processed after release, preventing concurrent gcCache() erasures from invalidating iterators.
  • Fix: heap-use-after-free in MonitorServer — inherits enable_shared_from_this; detached SSE handler threads capture shared_from_this() so the object stays alive until all threads finish.
  • Fix: DNS server UDP kicker — each kicker socket now binds to a unique ephemeral port so SO_REUSEPORT distributes dummy packets to all workers (previously all went to the same worker).
  • Fix: Monitor server misleading log on bind failure — acceptor_.close() now called so start() correctly skips "listening" message.
  • Fix: DNS resolution loop when system DNS routes through lynx — resolveHost() tries hardcoded IPs first to avoid recursing back into lynx via systemd-resolved.
  • Fix: Dashboard SSE error spam — removed broken health check path; SSE now properly streams JSON without disconnecting.
  • Refactor: Recovery architecture — lynx-loop is the sole process restarter (while loop); watchdog only monitors network state and updates proxy config. Both scripts use set +e for resilience.

v0.3.0

2026-07-01

  • Feature: Multi-upstream racing — secondary DoH server via --https_upstream2 / config.json. Queries fan out to both upstreams in parallel; fastest response wins.
  • Feature: Per-upstream health tracking (UpstreamPool.errors/successes). Pools with >30% error ratio shrink; healthy pools grow.
  • Feature: TCP keepalive (KEEPIDLE=10s, KEEPINTVL=3s, KEEPCNT=3) on all DoH connections — dead upstreams detected in ~30s.
  • Feature: scripts/setup-system-dns.sh — grants cap_net_bind_service, detects DNS manager (NetworkManager/systemd-resolved/resolvconf/static), sets system DNS to 127.0.0.1, saves backup for --restore.
  • Fix: Dead UDP socket in DNS server — main udpSocket_ was bound but never read from (async receive was never started). Kernel silently queued packets there; started async receive to fix.
  • Fix: Socket timeout increased to 5000ms (was 200ms) — prevents retry floods through slow proxies (e.g. PdaNet tether at 2-3s RTT).
  • Fix: Cache-miss fan-out re-enabled (CachingResolver::query) — auto-tuner now controls fan-out globally for misses too.
  • Refactor: Connection pool moved from single vector to deque<UpstreamPool> — each upstream gets independent pool with mutex and health counters.

v0.2.0

2026-06-25

  • Fixed: Proxy path in Connection::open() — missing return true after successful proxy TLS handshake. Execution always fell through to the direct connection block, overwriting the proxy tunnel. The daemon had never actually used the proxy since the fallback was added.
  • Fixed: Prewarm bypassing the cache. prewarmCache() in HttpResolver::init() called resolver->query() directly on the HTTP resolver, bypassing the CachingResolver. Moved to main.cpp and runs through the caching layer so entries populate both L1 turbo and L2 LRU.
  • Fixed: healthCheck() double-decrement bug — removed all mc.connected->store(false) calls from health check. The callers already handle the connected → false transition via exchange(false) with conditional fetch_sub(1). With health check pre-setting the flag, the caller's exchange saw false and skipped the decrement, leaking connectedCount_ by +1 per failure.
  • Changed: Auto-tuner now grows connections based on pool utilization. When utilization > 85% and QPS > 5, adds 1–2 connections immediately (instead of waiting for high latency or errors). Lowers growth thresholds (latency 300→200ms, trend 10→5, error rate 0.03→0.02).
  • Changed: Removed redundant "Resource Usage" section from dashboard GUI — info was already shown in the four summary cards.
  • Performance: Benchmark results with 8 concurrent workers:
    • Cache-hit P95: 2.2ms (well under 100ms target)
    • Mixed workload P95: 67.5ms (under 100ms target)
    • Cache-miss (unique domains): P95 329ms — dominated by PdaNet proxy round-trip latency (~100ms)
