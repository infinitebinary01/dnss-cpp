Lynx Changelog

DNS-over-HTTPS proxy — C++ port of dnss

v0.7.1 2026-07-08

  • Added: LatencyManager — urgency-driven scaling (0-5) with bottleneck detection
  • Added: latency_manager object in /api/stats JSON (urgency, gap%, bottleneck, targets)
  • Added: LM feeds threadBoost/connBoost/cacheRefreshBoost into the auto-tuner
  • Added: LM forces fan-out on and boosts cache refresh when urgency > 0
  • Fixed: warmupCache() called back_->query() bypassing CachingResolver — warmup never populated the HTTP cache since v0.7.0. Changed to this->query().
  • Fixed: ThreadPool initialized liveCount_ to n then spawned n workers, each adding 1 — counting to 2n. All workers immediately exited via the shrink loop because liveCount_ > target_. The pool was permanently understaffed (showed workers: 0 in telemetry).
  • Fixed: perfMonitorLoop thread started after warmupCache() — warmup blocks for ~80s doing 40 sequential HTTP requests. Moved thread start to before resolver_->init() so thread pool stats are recorded immediately.

v0.7.0 2026-07-08

  • Added: Persistent disk cache — binary serialization of L2 cache to configurable cache_file, save on destructor, load on startup
  • Added: Startup warmup — pre-resolves top 20 domains (A+AAAA) via warmupCache() in CachingResolver::init()
  • Added: Thread growth for high utilization + latency (util > 0.8 && lat > 200) — catches parallelism bottlenecks, not just queue depth
  • Added: Preemptive thread scaling (util > 0.5 && trend > 3) — analogous to cache prewarm
  • Added: Auto-flush excess threads: when threads > connections × 1.2, shrink threads to match
  • Fixed: Cache LRU eviction — instead of refusing to cache when full, evicts the entry with shortest remaining TTL
  • Fixed: needsRefresh() unit mismatch (nanoseconds vs seconds) — preemptive refresh was dead code
  • Fixed: TTL inflation on disk cache load — clobberTTL() zeros remaining TTL into loaded messages
  • Fixed: Fan-out TOCTOU race — uses compare_exchange_weak instead of load+store
  • Fixed: Proxy saturation only triggers when connections are underutilized (<70%)
  • Fixed: GUI labels: THREADS → THREAD POOL, PENDING → QUEUED, ALLOCATED → WORKERS
  • Fixed: Added actual thread_pool.workers to JSON/Prometheus API (separate from recommended)
  • Changed: Cache sizes increased — L2 2000→50000, L1 1024→4096, minTTL 30s→120s
  • Changed: Baselines — MIN_CONNS 6→16, MIN_THREADS 4→12, MAX_CONNS 48→64, pool start 8→12
  • Changed: Consecutive low load threshold 6→3 for faster idle shrink

v0.6.2 2026-07-04

  • Fixed: Balance threads-to-connections ratio under turbo load — prevent over-threading when connection pool is saturated

v0.6.1 2026-07-04

  • Fixed: Error rate inflation from duplicate watchdog race condition

v0.6.0 2026-07-04

  • Added: Turbo threader — aggressive thread scaling (+8/cycle, 16→64 max) when pending queue exceeds 50; capped decay prevents PID lockout
  • Added: Backpressure — tryEnqueue() rejects at queue ≥ 2000, returns SERVFAIL
  • Fixed: resize() used workers_.size() (never shrinks) instead of liveCount_ — pool permanently understaffed after shrink
  • Fixed: workerLoop() double-decremented liveCount_ on shrink exit
  • Fixed: async_send_to buffer use-after-free in onUdpReceive rejection path
  • Fixed: Uncaught DnsMessage::parse() exception in onUdpReceive
  • Changed: MAX_WORKERS 32→64, restart window 2s→0.5s

v0.2.0 2026-06-25

  • Fixed: Proxy path in Connection::open() — missing return true after successful proxy TLS handshake. Execution always fell through to the direct connection block, overwriting the proxy tunnel. The daemon had never actually used the proxy since the fallback was added.
  • Fixed: Prewarm bypassing the cache — prewarmCache() called resolver->query() directly on the HTTP resolver, bypassing CachingResolver. Moved to main.cpp and runs through the caching layer.
  • Fixed: healthCheck() double-decrement bug — removed all mc.connected->store(false) calls from health check.
  • Changed: Auto-tuner grows connections based on pool utilization (>85% + QPS > 5 adds 1–2 connections immediately). Lowered growth thresholds (300→200ms, 10→5 trend, 0.03→0.02 error rate).
  • Changed: Removed redundant "Resource Usage" section from dashboard GUI.

v0.1.1 2026-06-20

  • Fixed: Negative active connection count in stats dashboard — Connection::exchange() no longer sets connected = false on errors; all three unconditional connectedCount_ decrements now use exchange(false) and only decrement when the old value was true.
