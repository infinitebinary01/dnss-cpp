Project Overview

S
SystemResolver

Three-strategy DNS resolution: getaddrinfo() (system nsswitch/D-Bus, ~1ms), raw UDP to system nameservers (~5ms), DoH via libcurl (~100ms). Circular dependency detection for systemd-resolved. Auto-adapts on network changes.

C
Caching

Dual-tier: L1 turbo cache (4096-slot spinlock, lock-free reads) + L2 LRU map. Stale-while-revalidate with bounded worker queue. Preemptive refresh. Adaptive prewarm. Binary disk persistence.

A
Auto-Tuning

Kalman-filtered PID controller. LatencyManager urgency levels (0–5) with bottleneck detection. Dynamically adjusts connection count, thread pool, cache TTLs, fan-out, and refresh rates.

Component Deep Dive

DS
DnsServer core

dns_server.hpp/cpp — 677 LOC

Listens on UDP and TCP simultaneously using SO_REUSEPORT with 16 kernel-level worker threads. Each worker opens its own socket, eliminating accept contention.

  • Inline cache peek — UDP workers call peekCache() before enqueueing, bypassing the thread pool for cache hits (sub-millisecond).
  • Backpressure — tryEnqueue() with limit of 2000; when full, falls back to inline resolution instead of SERVFAIL.
  • Rate limiter — Sharded token bucket (16 shards, FNV-1a hash) — 100 queries/sec per client IP.
  • TCP — Separate thread pool (16 workers, 32 limit) prevents TCP from starving UDP.
  • Domain overrides — Per-domain upstream routing via DomainMap.
  • .local rejection — Returns NXDomain for mDNS (RFC 6762).
  • Graceful shutdown — Self-connect + dummy UDP packets to unblock I/O.
CR
CachingResolver core

caching_resolver.hpp/cpp — 635 LOC

Dual-tier cache wrapping any Resolver backend. Implements the Resolver interface (decorator pattern).

  • L1 Turbo Cache — 4096 direct-mapped slots with per-slot atomic_flag spinlocks. FNV-1a hash. Reads are lock-free after acquire. _mm_pause() on spin.
  • L2 LRU Cache — unordered_map with shared_mutex (readers-writer). Eviction by shortest remaining TTL when full (50k max).
  • Stale-while-revalidate — Serves expired entries within stale threshold (configurable), refreshes via bounded deque (max 64) + single worker thread.
  • Preemptive refresh — Background thread checks every 10s, refreshes entries when remaining TTL drops below refreshThresholdPct (AutoTuner-controlled).
  • Adaptive prewarm — Every 60s, re-queries top-10 most-queried domains (tracked in prewarmTracker_).
  • Dynamic TTL — Static atomics for minTTL (default 600s), negativeTTL (300s), staleThreshold (300s). AutoTuner adjusts up to 7200s.
  • Disk persistence — Binary format with magic 0x4C594E58 ("LYNX"), versioned. Saved on shutdown, loaded on start.
  • Error caching — Upstream failures cached as SERVFAIL with short TTL (negativeTTL/10, 30–60s).
SR
SystemResolver core

system_resolver.hpp/cpp — ~350 LOC

Three-strategy DNS resolver that auto-detects the best path on any network. Implements the Resolver interface.

  • getaddrinfo() — Leverages system nsswitch/D-Bus resolution. Fast (~1ms). Works on networks where systemd-resolved has real upstreams. Timed probe detects circular dependency.
  • Raw UDP — Direct queries to system nameservers (from /etc/resolv.conf + 1.1.1.1/8.8.8.8 fallback). 3s timeout per server. Works on networks with direct DNS access.
  • DoH via libcurl — HTTP POST to dns.google, cloudflare-dns.com, dns.quad9.net. 5s timeout. Auto-detects HTTP proxy from environment variables. Works through corporate proxies and captive portals.
  • Circular dependency detection — Detects when resolv.conf points to loopback (systemd-resolved). Probes getaddrinfo with 2s timeout; if it hangs, marks as circular and skips for future queries.
  • Network re-probe — Background thread every 60s re-checks UDP availability and getaddrinfo safety. Automatically adapts when switching networks.
  • Query priority — A/AAAA queries try getaddrinfo → UDP → DoH. Other types (MX, TXT, NS, SOA) go directly to UDP → DoH.
  • No connection pool — Stateless queries, no warmup wait. Server starts instantly.
NP
Network Probe infra

Built into SystemResolver — background thread that monitors network state.

  • UDP probe — Sends DNS query to 1.1.1.1, 8.8.8.8. 2s timeout. Sets udpWorks_ flag.
  • getaddrinfo probe — First query only. 2s timeout. If hangs, marks circular dependency. Sets getaddrinfoWorks_ flag.
  • Re-probe loop — Every 60s, re-checks UDP. Logs network changes. Adapts strategy automatically.
  • No connection management — Stateless queries, no pool to maintain. Server starts instantly.
AT
AutoTuner intelligence

auto_tuner.hpp/cpp — 536 LOC

Kalman-filtered PID controller that adapts the system in real-time. Runs every 3 seconds.

  • Kalman filter — Smooths raw latency with process noise 0.01, measurement noise 5.0. Prevents over-reaction to spikes.
  • PID controller — Kp=1.0, Ki=0.3, Kd=0.5. Anti-windup clamps integral to ±5. Output drives connection and thread growth decisions.
  • Turbo scaling — When pending queue > 50 for 2+ cycles, aggressively adds up to 4 connections and 8 threads per cycle.
  • Anomaly detection — Stuck queue (> 200 pending, 3+ cycles), error spike (> 3%, 2+ cycles), hit rate collapse (< 50%). Triggers cooldown (6 cycles / ~30s).
  • Connection management — Range 24–48. Grows on high utilization (> 90%), trend, errors. Shrinks on idle, proxy saturation.
  • Thread management — Range 12–24. Turbo-aware. Tracks threads vs connections ratio (cap at 1.2x).
  • Fan-out control — Enabled during boot, errors, high latency, variance. Disabled on stable low load after 24 samples.
  • Cache TTL tuning — Increases minTTL/negativeTTL on high latency + low hit rate (up to 7200s). Decreases on low latency + high hit rate.
  • PID damping — 10-second holdoff between connection count increases (reductions immediate).
LM
LatencyManager intelligence

latency_manager.hpp/cpp — 132 LOC

Urgency-driven controller that evaluates how far actual latency is from targets. Feeds into AutoTuner.

  • Gap computation — Ratio of actual to target latency (both avg and P95). Smoothed with EWMA (0.7/0.3). Gap = max(avgRatio, p95Ratio).
  • Urgency levels — 0 (on target) to 5 (gap > 10x). Consecutive-over boost (3+ → +1, 6+ → +1, capped at 5).
  • Bottleneck detection — First-match: queue (load > 10) → cache (hit rate < 50%) → upstream (conn util > 90%).
  • Boost computation — Thread boost: urgency × 3 (queue), × 2 (upstream). Conn boost: urgency × 2 (upstream/cache). Cache refresh: 4–12% additive.
  • Targets — Default: avg 50ms, P95 200ms. Configurable via setTargets().
PM
PerfMonitor telemetry

perf_monitor.hpp/cpp — 138 LOC

Central telemetry hub. All subsystems record metrics here; AutoTuner and MonitorServer read from here.

  • Latency ring buffer — 256-slot lock-free ring. atomic<uint64_t> per slot. Write index via fetch_add. Snapshot sorts for avg/P95.
  • Atomic counters — cacheHits, cacheMisses, errors, queries. All memory_order_relaxed.
  • Noise filter — Thread-local flag. Background queries (prewarm, refresh) marked as noise — excluded from user-visible stats.
  • Per-domain latency — EWMA tracking per base domain (2-label extraction). Exported for dashboard.
  • Supplementary stats — Callback function for CachingResolver to inject turbo/stale hit rates into snapshot.
  • Error decay — decayErrors() halves the error counter each cycle (called by AutoTuner).

HS
HttpsServer optional

https_server.hpp/cpp — 239 LOC

Reverse proxy: accepts DoH queries from clients (TLS or plain HTTP) and forwards to a local DNS upstream. Built on Boost.Beast.

  • TLS + plain HTTP — Toggle via --insecure_http_server. TLS uses tlsv12_server with cert/key files.
  • Endpoints — /dns-query and /resolve (POST only, application/dns-message).
  • Per-connection thread — Each accepted connection spawns a detached thread (simple model, low-traffic path).
  • DNS upstream — Forwards to configurable UDP DNS server (default 8.8.8.8:53).
DP
dns_protocol protocol

dns_protocol.hpp/cpp

DNS wire format parser and serializer. Everything DNS-related flows through this.

  • Structs — DnsHeader (bitfield accessors), DnsQuestion, DnsResourceRecord, DnsMessage.
  • Parse/Pack — Binary wire format round-trip. Handles compression pointers (jump count limit: 10).
  • SSE4.2 acceleration — dns_helpers::nameEquals() processes 16 bytes at a time with _mm_cmpeq_epi8, _mm_cmpeq_epi8 for case-insensitive compare. Falls back to scalar for tails < 16 bytes.
  • Factory methods — createQuery(), createReply(), createError(), copy().
  • Helpers — wireToName() (inline buffer), nameToWire(), rdataToUint16/32().

Cache Subsystem — Dual-Tier Architecture

L1 Turbo Cache hot path

Slots4,096 (power-of-2, mask-indexed)
IndexingFNV-1a hash → h & (4096-1)
LockingPer-slot atomic_flag spinlock with _mm_pause()
LookupCompare keyHash atomic, check expiry
EvictionDirect-mapped (oldest-wins on collision)
PopulateOn L2 hit or fresh upstream response
Latency~100ns (atomic load + compare)

L2 LRU Cache main store

Structureunordered_map<CacheKey, CacheEntry>
Lockingshared_mutex (readers-writer)
Max size50,000 entries
EvictionShortest remaining TTL when full
GCBackground thread every 30s removes expired
StaleExpired entries served within staleThreshold, async refresh
RefreshBounded deque (64 max) + single worker thread

Cache Lookup Flow

query(req)
  │
  ├── 1. turboLookup(h) ──→ HIT: return buildCachedReply()     [~100ns, lock-free]
  │
  ├── 2. L2 cache_.find(key) under shared_lock
  │     ├── fresh ──→ HIT: turboInsert(), return              [populates L1 for next time]
  │     └── expired but within staleThreshold
  │           ──→ STALE HIT: turboInsert(60s), enqueue refresh, return
  │
  ├── 3. MISS → back_->query(req)
  │     ├── success → shouldCache()? → computeCacheTTL()
  │     │     → clobberTTL() → store in L2 + turboInsert()
  │     └── failure → cache SERVFAIL with short TTL (30-60s)
  │
  └── Return reply
